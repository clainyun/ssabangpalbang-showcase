# 싸방팔방 최종 시연 시나리오

> 목표 시간: 약 10분 (예비 2분 포함 12분)
> 대상 빌드: Android 시연 APK(`demo` 프로필) · 운영 API `https://legacy.example.com`
> 원칙: 실제 비밀번호·토큰·이메일·실거주지 정보를 발표 화면에 노출하지 않는다.

이 문서는 발표자가 **화면을 보면서 그대로 따라 할 수 있도록** 화면별 진입 경로, 눌러야 하는 버튼의
위치와 이름, 그때 확인해야 하는 포인트를 순서대로 적은 것이다. 버튼 이름은 실제 앱에 표시되는
문구와 접근성 라벨을 그대로 사용했다.

---

## 1. 화면 구조

### 1.1 하단 탭바 — 5개, **`홈`이 가운데(3번째)**

화면 하단에 떠 있는 알약(pill) 모양 바다. 좌측부터 순서가 고정돼 있다.

| 위치 | 탭 | 라우트 | 역할 |
|---:|---|---|---|
| 1 (맨 왼쪽) | `지도` | `/(tabs)/map` | 지도 기반 아파트 탐색 |
| 2 | `커뮤니티` | `/(tabs)/community` | 게시글·후기 |
| 3 (**가운데**) | `홈` | `/(tabs)/home` | 앱 진입 기본 탭 |
| 4 | `찜` | `/(tabs)/wishlist` | 관심 단지·리포트 |
| 5 (맨 오른쪽) | `마이` | `/(tabs)/my` | 내 활동·일정 |

> 발표 중 길을 잃으면 **가운데 `홈`을 누르면 원점**으로 돌아온다.

### 1.2 탭 밖 주요 화면

| 화면 | 라우트 | 진입 경로 |
|---|---|---|
| 아파트 상세 | `/apartment/[id]` | 지도 마커·검색 결과·찜 목록 |
| 스터디 상세 | `/study/[id]` | 아파트 상세 → `함께 임장하기` |
| 스터디 채팅 | `/chat/[roomId]` | 스터디 상세 우측 상단 채팅 아이콘 |
| 임장 대기 | `/field-visit-waiting/[studyId]` | 스터디 상세 → `임장 시작하기` |
| 현장(임장 진행) | `/field/[sessionId]` | 임장 대기 화면에서 세션 시작 후 자동 이동 |
| 임장 요약 | `/field-summary/[sessionId]` | 현장 화면 → `임장 끝내기` → `종료하기` |
| 리포트 생성 중 | `/report-generating/[reportId]` | 임장 요약 → `리포트 보러가기` |
| 리포트 상세 | `/report/[reportId]` | 생성 완료 후 자동 이동 · 아파트 상세 → `현장 기록 보기` |

## 2. 시연 전 준비

### 2.1 서버·인프라 (발표 30분 전)

- [ ] `curl -fsS https://legacy.example.com/actuator/health` → `UP`
- [ ] `bash infra/scripts/prod-smoke-test.sh` 전 항목 통과 (HTTPS 308 · 무인증 401 · `/ws` 101)
- [ ] `docker compose -f infra/docker-compose.prod.yml ps --all` → `postgres`·`redis`·`kafka`·`app`·`ai` healthy
- [ ] AI(GMS Gemini) 키 유효성 확인 — 챗봇에 아무 질문이나 1회 던져 응답 확인
- [ ] FCM 발송 1회 테스트 (임장 종료 요청 Push 경로)

### 2.2 기기·앱

- [ ] 시연 APK 설치, 운영 API에 연결됨을 로그인으로 확인
- [ ] 발표용 계정 **로그인 상태로 미리 진입**해 둔다 (STEP 1에서 로그아웃 상태로 되돌릴지 결정)
- [ ] 위치 권한 `앱 사용 중 허용`, 카메라·마이크 권한 허용 완료
- [ ] 기기 방해금지 모드 ON, 화면 자동 꺼짐 10분 이상, 배터리 절전 OFF
- [ ] 미러링(scrcpy 또는 무선 디스플레이) 연결 확인

### 2.3 시연 데이터 사전 준비 — **여기가 리허설의 핵심**

- [ ] 대상 아파트 1곳 확정 (지도에서 바로 찾을 수 있는 위치)
- [ ] 그 아파트에 **모집 중 스터디 1개** + 발표 계정이 스터디장
- [ ] **완료된 임장 리포트 1개**를 미리 생성해 둔다 → STEP 12가 실패해도 이걸로 대체
- [ ] 스터디 채팅에 이전 메시지 3~5건 (빈 채팅방은 화면이 허전하다)
- [ ] 커뮤니티에 대상 아파트가 연결된 게시글 1건
- [ ] 챗봇 대화를 **한 번 미리 실행**해 임베딩·색인이 준비된 상태로 만든다

### 2.4 화면 정리·개인정보

- [ ] 알림바에 개인 메시지 미리보기가 뜨지 않게 설정
- [ ] 프로필 사진·닉네임이 실명·실사진이 아닌지 확인
- [ ] 지도 첫 진입 위치가 발표자 실거주지가 아닌지 확인
- [ ] 화면 녹화본(예비 영상) 준비 — 네트워크 장애 시 대체

## 4. 단계별 상세

### STEP 1 — 로그인 (0:20)

**화면** `/(auth)/login`

**조작**
1. 앱 아이콘 실행 → 로그인 화면 진입
2. `이메일` 입력란 탭 → 발표용 계정 입력
3. `비밀번호` 입력란 탭 → 입력. **키보드 입력 화면이 미러링에 그대로 보이므로 미리 저장된 자동완성 사용을 권장**
4. `로그인` 버튼 탭

**확인 포인트** 인증 성공 후 가운데 `홈` 탭으로 자동 이동

**멘트** "싸방팔방은 아파트를 혼자 검색하는 서비스가 아니라, 관심사가 비슷한 사람들과 임장 스터디를 만들고 현장에서 확인한 사실을 함께 기록하는 서비스입니다."

> 화면 아래쪽에 `간편 로그인`(카카오·네이버), `회원가입`, `비밀번호 재설정`이 있다. **소셜 로그인은 외부 서비스 의존이라 발표 기본 동선에서는 쓰지 않는다.** 언급만 하고 넘어간다.

---

### STEP 2 — 홈 (0:30)

**화면** `/(tabs)/home` · **진입** 로그인 직후 자동

**조작**
1. 상단 날씨 영역을 손으로 가리키며 설명 (`오늘 현재 날씨`, 대기질 `좋음`/`보통`/`나쁨`/`매우나쁨`)
2. `다음 임장까지` 카운트다운 카드를 가리킨다
3. 아래로 스크롤해 `내 스터디 만들기` · `스터디 찾기` 진입점 노출

**확인 포인트** 다음 임장 D-day가 실제 스터디 일정과 일치하는지

**멘트** "홈에서는 다음 임장까지 남은 시간과 그날의 날씨·대기질을 먼저 보여줍니다. 임장은 결국 현장에 나가는 활동이라 날씨가 중요합니다."

> 우측 상단 `설정 열기`(톱니) 옆에 `시연용 개발자 모드`가 있다 — 시연 APK에서만 보인다. **STEP 8에서 GPS가 안 잡힐 때만 사용**한다. §6 참조.

---

### STEP 3 — 지도 탐색 (0:50)

**화면** `/(tabs)/map` · **진입** 하단 탭바 **맨 왼쪽 `지도`**

**조작**
1. 지도가 뜨면 우측의 `내 위치로 이동` 버튼 탭 (권한 거부 시 `위치 켜기` 안내가 뜬다)
2. 두 손가락으로 대상 아파트 주변까지 이동·확대
3. 상단 `아파트 검색` 입력란 탭 → 대상 아파트 이름 입력 → 검색 결과에서 선택
4. 시설 필터를 열어 `교통` · `생활` · `의료` · `학군` · `환경` 중 1~2개 선택 → 주변 시설 마커 표시
5. 하단 시트를 위로 **끌어 올려** `내 주변 아파트` 목록 확인 (`현재 영역 N개 단지` 표기)
6. 대상 아파트 마커 또는 목록 카드 탭

**확인 포인트** Mapbox 타일 로딩, 마커 클러스터링, 시설 필터 즉시 반영

**멘트** "지도에서 원하는 지역을 보면서 단지를 찾고, 교통·학군·의료 같은 조건으로 주변 시설을 함께 확인할 수 있습니다."

> **타일 로딩이 3초 이상 지연되면** 검색으로 바로 넘어간다. §7 대체 동선.

---

### STEP 4 — 아파트 상세 (0:50)

**화면** `/apartment/[id]` · **진입** STEP 3에서 마커/카드 탭

**화면 배치**
- **좌측 상단** — `뒤로 가기`(‹)
- **우측 상단** — `공유하기`, **하트(`아파트 찜하기`/`아파트 찜 해제`)**
- **중앙 상단** — 단지명, 주소, 준공 정보
- **중앙** — 단지 요약 정보 버블(세대수·주차·최근 실거래 등)
- **하단 좌** — `함께 임장하기` (부제 `스터디 N개`)
- **하단 우** — `현장 기록 보기` (부제 `리포트 N개`)
- **우측 하단** — 팔방이 캐릭터 챗봇 FAB (드래그로 위치 이동 가능)

**조작**
1. 단지명·주소·준공 연월을 짚어가며 설명
2. 요약 정보 버블을 좌우로 넘겨 최근 실거래가 확인
3. **`현장 기록 보기`** 탭 → `임장 리포트` 시트가 올라오며 `완료된 현장 리포트` 목록 표시 → 시트를 내려 닫는다

**확인 포인트** 실거래 데이터 표시, 리포트 개수와 시트 내용 일치

**멘트** "단지 상세에서는 실거래 정보와 함께, 이 단지에서 모집 중인 스터디와 이전에 다녀간 사람들이 남긴 임장 리포트를 한 번에 볼 수 있습니다."

---

### STEP 5 — 찜 (0:20)

**조작**
1. 아파트 상세 **우측 상단 하트** 탭 → 채워진 하트로 변경 (`아파트 찜 해제` 라벨로 바뀜)
2. 하단 탭바 **4번째 `찜`** 탭
3. 상단에서 `관심 단지` ↔ `리포트` 전환을 한 번 보여준다
4. `겹쳐 보기` ↔ `목록 보기` 전환, 정렬(`최근순`·`이름순`) 노출
5. 방금 찜한 단지가 목록에 있는지 확인

**확인 포인트** 찜 등록이 즉시 반영되고 목록에서 보인다 (등록/해제는 멱등 처리)

**멘트** "관심 단지와 마음에 든 리포트를 따로 모아둘 수 있습니다."

> 다음 단계로 가려면 **뒤로 가기 또는 `지도` 탭 → 아파트 상세로 복귀**한다.

---

### STEP 6 — 스터디 상세 (0:50)

**화면** `/study/[id]` · **진입** 아파트 상세 하단 좌측 **`함께 임장하기`** → `함께 임장할 스터디` 시트 → 대상 스터디 카드 탭

**조작**
1. 시트에서 스터디 상태 뱃지 확인 (`모집 중` · `마감 임박` · `일정 조율 중`)
2. 스터디 카드 탭 → 상세 진입
3. 위에서 아래로 스크롤하며 `스터디 소개` → `스터디 목표` → 멤버 목록 → `스터디 공지` 순서로 설명
4. `공지 더 보기` 탭 → 공지 목록 확인 후 뒤로
5. 스터디장 계정이면 `신청자 관리` 진입 → 신청자 승인/거절 UI를 **보여주기만** 하고 뒤로

**확인 포인트** 소개·목표·멤버·공지·일정이 모두 채워져 있는지 (빈 섹션이 있으면 사전 준비 미흡)

**멘트** "스터디에는 목표와 공지, 멤버, 일정, 실시간 채팅이 모두 연결돼 있습니다. 스터디장은 신청자를 직접 승인하고 모집을 마감할 수 있습니다."

> 우측 상단에 `스터디 공유하기`, `스터디 더보기`(모집 마감·나가기 등)가 있다.

---

### STEP 7 — 스터디 채팅 (0:30)

**화면** `/chat/[roomId]` · **진입** 스터디 상세의 채팅 아이콘(`스터디 채팅 열기`)

**조작**
1. 채팅방 진입 → 이전 메시지 로딩 확인
2. 하단 입력창에 짧은 메시지 입력 후 전송 (예: `현장에서 뵙겠습니다`)
3. **가능하면 보조 발표자의 두 번째 기기에서 답장** → 양쪽에 즉시 표시되는 것을 보여준다
4. 뒤로 가기 → 스터디 상세 복귀

**확인 포인트** 전송 직후 즉시 반영, `연결 중...` 상태로 멈추지 않음, 30초 이상 연결 유지

**멘트** "채팅은 WebSocket STOMP 기반이라 새로고침 없이 실시간으로 오갑니다."

---

### STEP 8 — 임장 시작 (0:30)

**화면** `/field-visit-waiting/[studyId]` → `/field/[sessionId]`

**조작**
1. 스터디 상세 하단의 **`임장 시작하기`** 탭 (스터디장이 아니면 `임장 참여하기` 또는 `임장 일정 확인`으로 표시)
2. 위치 권한 확인 (`위치 권한 필요` 안내가 뜨면 허용)
3. 임장 대기 화면에서 참여자 합류 상태 확인
4. 세션이 시작되면 현장 화면으로 자동 이동

**확인 포인트** 대상 아파트와의 **거리 검증**이 동작한다 — 멀리 있으면 시작이 막힌다

**멘트** "임장은 실제로 현장에 있어야 시작됩니다. 대상 아파트와의 거리를 검증해서 현장성을 지킵니다."

> **발표장은 대상 아파트에서 멀기 때문에 여기서 막힐 수 있다.** §6의 가상 위치를 미리 켜 두거나, 이미 시작된 세션으로 재진입한다.

### STEP 9 — 현장 화면 (0:40)

**화면** `/field/[sessionId]`

**화면 배치**
- **상단** — 뒤로 가기, `스터디 채팅 열기`
- **지도 영역** — 내 위치 핀, 이동 궤적, `대상 아파트` 마커, `현재 위치로` 버튼
- **하단 시트** — 체크리스트 (위로 끌어 올리면 전체 목록)
- **우측 하단** — 팔방이 챗봇 FAB
- **하단** — `임장 끝내기`

**조작**
1. 지도에서 내 위치와 이동 궤적 확인, `현재 위치로` 탭
2. 하단 체크리스트 시트를 **위로 끌어 올린다**
3. 카테고리별 항목을 스크롤하며 보여준다 (`교통`·`생활`·`의료`·`학군`·`환경`·`기타`)
4. 상단에서 참여 인원·진행 상태 확인

**확인 포인트** 체크리스트가 **AI로 생성된 개인 맞춤 항목**이라는 점, 궤적선이 실시간으로 그려지는 점

**멘트** "현장에 도착하면 참여자마다 관심사에 맞춘 체크리스트가 자동으로 만들어집니다. 이동 경로는 계속 기록됩니다."

### STEP 10 — 현장 기록 (1:10) — **가장 중요한 단계**

**조작**
1. 체크리스트에서 항목 하나 탭 → **`기록 남기기`**
2. **텍스트** — 메모 입력 후 `메모 저장`
   - 예: `정문에서 지하철역까지 도보 접근이 편했습니다.`
3. **사진** — `카메라`로 즉석 촬영하거나 `사진 선택`으로 앨범에서 선택 → 업로드 완료 확인
4. **음성** — `음성 메모` 탭 → 녹음 시작(`녹음 중` 표시) → 5~8초 말하고 종료
   - 예: `대로변 동은 차량 소음이 크게 느껴졌습니다.`
   - `음성 변환 대기 중…` → 잠시 후 **텍스트로 변환되어 표시**
5. 항목을 `완료로 표시` → 진행률 증가 확인
6. `기록 보기`로 전환해 `저장된 메모` 목록 확인

**확인 포인트** STT 변환 결과가 실제 발화와 맞는지, 사진이 목록에 뜨는지, 진행률이 올라가는지

**멘트** "현장에서는 손으로 타이핑하기 어렵습니다. 그래서 사진과 음성을 그대로 남기면 음성은 STT로 텍스트가 되고, 이 기록들이 그대로 AI 리포트의 근거가 됩니다."

> **메모는 2~4건만 남긴다.** 너무 많으면 STEP 12의 리포트가 길어져 발표 시간을 넘긴다.
> STT가 10초 넘게 지연되면 기다리지 말고 **미리 변환해 둔 기록**을 보여주며 넘어간다.

### STEP 11 — 임장 종료·요약 (0:40)

**조작**
1. 하단 **`임장 끝내기`** 탭
2. `임장을 종료할까요?` 확인 다이얼로그 → **`종료하기`**
3. 임장 요약 화면(`/field-summary/[sessionId]`)으로 이동
4. `임장을 마쳤어요` 헤더, **`오늘의 임장 경로`** 지도(`출발`·`도착` 마커와 궤적선) 확인
5. `이동 거리` · `소요 시간` · `평균 속도` 지표를 짚어준다
6. 필요하면 `이미지 저장`으로 경로 이미지 저장 시연

**확인 포인트** 궤적선과 출발/도착 마커가 제대로 그려지는지

**멘트** "임장을 마치면 이동한 경로와 거리, 소요 시간이 요약됩니다."

> 여러 명이 참여 중이면 `팀원 기다리기`가 뜬다. 전체 마감은 `강제 종료 요청하기` → 다른 참여자가 `동의하기`로 진행되며, **이때 FCM Push가 발송된다.** 두 번째 기기가 있으면 이 Push를 보여주면 좋다.

---

### STEP 12 — AI 리포트 (1:00)

**조작**
1. 임장 요약에서 **`리포트 보러가기`** 탭
2. 생성 중 화면(`/report-generating/[reportId]`)에서 진행 상태 표시 — 이 사이에 아래 멘트를 한다
3. 완료되면 리포트 상세(`/report/[reportId]`)로 이동
4. **`긍정적인 의견`** 섹션 → `더보기`로 펼쳐 근거 확인
5. **`주의 의견`** 섹션 → 참여자 간 의견이 갈린 지점 강조
6. 각 주장에 연결된 **원본 현장 기록 근거**를 짚는다
7. 우측 상단 `리포트 찜하기` 1회 탭 → `찜` 탭의 `리포트`에서 확인 가능함을 언급

**확인 포인트** 리포트에 STEP 10에서 남긴 기록이 실제로 반영됐는지

**멘트** "참여자들이 임장을 마치면 Kafka 이벤트로 AI Worker가 기록을 정규화하고 의견을 분석해 리포트를 만듭니다. 핵심은 각 주장마다 원본 현장 기록이 근거로 연결된다는 점입니다. 근거 없는 문장은 만들지 않습니다."

> **생성이 40초를 넘기면 기다리지 않는다.** `돌아가기` 후 아파트 상세 → `현장 기록 보기` →
> **미리 만들어 둔 완료 리포트**를 열어 동일한 내용을 설명한다. 발표 흐름이 끊기지 않는다.

### STEP 13 — AI 챗봇 (0:50)

**진입** 아파트 상세 또는 현장 화면 **우측 하단 팔방이 FAB** 탭 → `임장 도우미` 모달

**조작**
1. FAB 탭 → 챗봇 모달 오픈
2. 하단 `메시지 입력...` 란에 질문 입력 후 전송
   - `이 아파트의 교통 관련 임장 의견을 요약해줘.`
3. 답변에 표시되는 **근거 출처**를 짚는다 (리포트 기반 / 웹 기반)
4. 두 번째 질문으로 의견 충돌을 물어본다
   - `소음에 대해 의견이 갈린 부분이 있어?`

**확인 포인트** 답변이 실제 리포트 내용을 인용하는지, 근거가 부족할 때 지어내지 않는지

**멘트** "생성된 리포트는 챗봇의 검색 근거로도 쓰입니다. 리포트에서 충분한 근거를 못 찾으면 웹 검색으로 전환하고 그 사실을 함께 표시합니다. 근거가 아예 없으면 사실을 만들어내지 않고 근거 부족으로 답합니다."

> 질문은 **리허설에서 검증한 것만** 쓴다. 즉흥 질문은 응답이 길어지거나 근거 부족으로 빠지기 쉽다.

## 6. GPS 시연

발표장은 대상 아파트에서 멀기 때문에 **STEP 8이 거리 검증에서 막힐 수 있다.** 대응 순서는 다음과 같다.

1. **1순위 — 시연용 가상 위치**
   시연 APK(`EXPO_PUBLIC_DEMO_MODE_ENABLED=true`) 또는 개발 빌드에서 **홈 화면의 `시연용 개발자 모드`**를 `활성화`하면 가상 위치를 설정할 수 있다. 현장 화면에서는 **가상 GPS 이동 조이스틱**으로 위치를 움직여 궤적선이 그려지는 것까지 보여줄 수 있다.
2. **2순위 — 이미 시작된 세션 재진입**
   리허설에서 시작해 둔 세션으로 들어가 STEP 9(현장 화면)부터 진행한다.
3. **3순위 — 녹화 영상**

> 스토어 `production` 빌드는 `EXPO_PUBLIC_DEMO_MODE_ENABLED`를 반드시 `false`로 강제하며, 값이 `false`가 아니면 EAS 빌드 자체가 중단된다. **시연 모드는 발표용 APK에만 존재한다** — 이 점을 심사위원에게 명확히 밝힌다.

실제 위치 기능을 그대로 보여줄 수 있는 상황(대상 아파트 근처)이라면 가상 위치를 쓰지 않는다.

## 7. 장애 시 대체 동선

| 장애 | 발표 중 대응 | 되돌아갈 지점 |
|---|---|---|
| 지도 타일 지연 | 상단 `아파트 검색`으로 바로 검색 | STEP 4 |
| 소셜 로그인 장애 | 이메일 발표용 계정 사용 | STEP 1 |
| GPS 거리 검증 실패 | `시연용 개발자 모드` 가상 위치 또는 시작된 세션 재진입 | STEP 9 |
| 사진 업로드 장애 | 미리 저장된 현장 기록 표시 | STEP 10 |
| STT 10초 이상 지연 | 이미 변환 완료된 기록 표시 | STEP 10 |
| 리포트 생성 40초 초과 | 아파트 상세 → `현장 기록 보기` → 미리 만든 완료 리포트 | STEP 12 |
| 챗봇 외부 API 장애 | 리포트 상세의 근거 화면으로 핵심 가치 설명 | STEP 12 |
| FCM 미수신 | 앱 내 알림 목록으로 이벤트 확인 | STEP 11 |
| 채팅 `연결 중...` 고착 | 채팅방 재진입 1회, 그래도 안 되면 건너뛴다 | STEP 8 |
| 앱 전체 응답 없음 | 앱 강제 종료 후 재실행 → 가운데 `홈`부터 재개 | STEP 2 |

**발표 중 절대 하지 않는 것** — 운영 DB 초기화, `docker compose down -v`, 앱 재배포, AI 모델 재다운로드.
